404 Error Fix

GitHub Pages —
Step by Step

Getting a 404 when clicking page links is the most common GitHub Pages issue. The fix is simple — your files just need to be uploaded correctly and in the right place. Follow every step below exactly.

Why are you getting a 404?
GitHub Pages serves files by their exact filename. If a file isn't uploaded, or is in a subfolder by accident, the link breaks. The most common causes are: (1) files uploaded inside a subfolder instead of the root, (2) the wrong branch selected, or (3) GitHub Pages not enabled yet. This guide fixes all three.
1
Go to Your GitHub Repository
1
Open your browser and go to github.com
2
Click your profile picture in the top right → click Your repositories
3
Click on your repo — it should be named something like yourfemalengineer.github.io
Don't have a repo yet? Go back to the Setup Guide (SETUP-GUIDE.html) and follow Step 2 first to create your repository.
2
Check That ALL Files Are in the Root (Not a Subfolder)

This is the #1 cause of 404 errors. When you upload a zip or a folder, GitHub sometimes puts all files inside a subfolder. Your files must be at the TOP LEVEL of the repo — not inside any folder.

← all your files are stuck in here
If you see a folder instead of your files: Click into the folder, select all files, and move them to the root. OR delete everything and re-upload — but this time unzip first and drag the individual files (not the folder).
How to check: When you open your repo on GitHub, you should see index.html listed immediately — not a folder name. If you see a folder name like github-pages-export, your files are in the wrong place.
3
How to Upload Files Correctly

Follow these steps exactly to upload all your files to the root level.

1
On your computer — find the yfe-final.zip file I gave you
Right-click it → Extract All (Windows) or double-click (Mac) to unzip it
2
Open the unzipped folder → open the github-pages-export folder inside it
You should now see all your files: index.html, about.html, style.css, logo.png, all the photos, etc.
3
Select ALL files inside that folder — press Ctrl+A (Windows) or Cmd+A (Mac)
Make sure you select the FILES, not the folder itself
4
Go to your GitHub repo in your browser
5
Click Add file → Upload files
6
Drag all your selected files directly into the upload box on GitHub
You should see all filenames appear — index.html, about.html, all photos, etc. If you see a folder name, start over and drag individual files instead
7
Scroll down and click the green Commit changes button
Wait about 30–60 seconds for GitHub to process the upload
After committing: Refresh your repo page. You should now see index.html and all your other files listed at the top level with no folders in between.
4
Make Sure GitHub Pages Is Turned On
1
In your repo, click Settings — it's in the top tab row
2
In the left sidebar, scroll down and click Pages
3
Under Source, make sure it says Deploy from a branch
If it says "None", click the dropdown and select "Deploy from a branch"
4
Under Branch, select main and folder / (root) → click Save
⚠️ The folder MUST be set to / (root) — not /docs or any subfolder
5
Wait 1–2 minutes, then refresh the Settings → Pages screen
You should see a green banner: "Your site is live at https://yourname.github.io"

Still getting a 404 on a specific page? Go back to your repo and check that file exists at the root level. For example if about.html gives a 404, search for about.html in your repo — if it's missing, upload it again following Step 3.
6
Connect Your GoDaddy Domain (Optional — Do This Last)

Only do this step after your site is working on the .github.io URL. Don't connect your domain until everything looks correct.

1
In GitHub: Settings → Pages → Custom domain field
Type your domain exactly: yourfemalengineer.com (use your actual domain)
2
Click Save
GitHub will create a CNAME file in your repo automatically — don't delete it
3
Log into godaddy.com → My Products → DNS (next to your domain)
4
Delete any existing A records (the ones pointing to GoDaddy's IP)
Look for records with Type "A" and Name "@" — delete all of them
5
Add these 4 new A records — one at a time:
TYPENAMEVALUE
A@185.199.108.153
A@185.199.109.153
A@185.199.110.153
A@185.199.111.153
CNAMEwwwyourfemalengineer.github.io
6
Save all records and wait 15–30 minutes
DNS takes time to update worldwide. Go make a coffee ☕ — it'll be ready when you get back.
7
Back in GitHub → Settings → Pages → check Enforce HTTPS
This gives you the secure padlock for free
You're live! Visit your domain — it should show your full site. If it still shows a GoDaddy parked page, wait another 30 minutes and try again. DNS can take up to 24 hours in rare cases.
❓
Common Errors & Quick Fixes
404 on every page → Your files are in a subfolder. Go to Step 3 and re-upload, dragging individual files not the folder.
404 on one specific page → That file is missing. Check your repo for that filename and upload it if it's not there.
Site shows but no styles / looks broken → style.css didn't upload. Go back to your repo and check — if it's missing, upload it.
Logo or photos not showing → Image files didn't upload. In your repo, look for logo.png and all the photo-*.jpg files. Upload any that are missing.
Site not updating after changes → Hard refresh your browser: Ctrl+Shift+R (Windows) or Cmd+Shift+R (Mac). GitHub Pages can take 1–2 minutes to rebuild.
Custom domain not working → Check your GoDaddy DNS records are exactly as shown in Step 6. Make sure the CNAME record points to yourname.github.io with your actual GitHub username.
